# 실제 데스크톱 동작 검증 기록

이 문서는 0.1.0의 초기 검증 기록입니다. 최신 이미지·500MB 파일 전송 검증은 [0.2.0 검증 기록](file-transfer-verification.md)을 참고하세요. `test-results/`와 `release/`의 파일은 최신 실행 결과로 갱신됩니다.

2026년 10월 20일 20:48 KST에 ClipSync 0.1.0의 Linux x64 패키지를 검증했습니다. 마지막 실행은 UTC 11:48:05–11:48:18이며, 아래 결과는 이 실행에서 생성된 기록과 화면 캡처에 근거합니다.

## 실행 환경과 방법

- 패키징된 `release/ClipSync-linux-x64/ClipSync` 실행 파일을 **두 프로세스**로 시작했습니다.
- 각 프로세스는 별도의 앱 프로필과 Xvfb 디스플레이(`:0`, `:1`)를 사용했습니다. 연결 전 두 OS 클립보드가 서로 영향을 주지 않는다는 검사를 통과했습니다.
- 호스트 화면에서 연결을 열고 복사한 초대 코드를 그대로 사용했습니다. 테스트가 주소나 세션 키를 바꾸거나 애플리케이션의 세션 구현을 직접 호출하지 않았습니다.
- 실제 편집기에 텍스트를 입력하고 키보드 복사·붙여넣기를 수행했습니다. 상대 앱의 OS 클립보드와 편집기에 기대한 내용이 도착했는지 확인했습니다.
- Chromium 샌드박스가 제공되지 않는 격리된 클라우드 컨테이너이므로 이 실행에만 `--no-sandbox`를 사용했습니다.

| 시나리오 | 확인한 동작 |
| --- | --- |
| 클립보드 분리 | 두 디스플레이의 클립보드가 독립적임 |
| 초대·인증 | 잘못된 형식과 세션 키 거부, 원래 초대 코드로 UI 참여, 연결 전 내용 미전송 |
| 양방향 복사·붙여넣기 | 한글·이모지·여러 언어·줄바꿈 보존, 양쪽 전송·수신 횟수 각각 1회, 반복 전송 없음 |
| 일시정지·재개 | 전송·수신 적용 차단, 정지 중 복사한 내용을 재개 시 유출하지 않음 |
| 이미지 클립보드 | 실제 PNG가 OS 클립보드에 있음을 확인하고 전송 제외, 상대 텍스트 유지, 다음 텍스트 정상 동기화 |
| 용량 경계 | UTF-8 정확히 1MiB 전송, 1바이트 초과 텍스트 거부, 이후 정상 텍스트 전송 |
| 동시 복사 | 5회 동시 복사 후 양쪽 내용 일치, 전송·수신 횟수가 안정되어 동기화 루프가 없음을 확인 |
| 연결 해제·재연결 | 해제 후 공유 중단, 새 세션이 이전 코드를 거부, 새 코드로 재연결 후 전송 |
| 호스트 종료 | 호스트 프로세스 종료 코드 0, 참여 앱의 연결 해제 감지와 오류 표시 |

검증 중 테스트 도구의 PNG 데이터 CRC 오류와 Blob의 TypeScript 타입 오류를 수정했습니다. 애플리케이션 기능 소스는 변경하지 않았습니다. 최종 기록은 수정 후 전체 시나리오를 다시 실행한 결과입니다.

## 재현

README의 클라우드 환경 변수를 설정한 뒤 저장소 루트에서 실행합니다.

```sh
npm run typecheck
npm test
npm run package
npm run test:pair
```

검증 코드는 `tests/desktop.pair.ts`에 있습니다. 테스트가 만든 앱과 가상 디스플레이는 종료 시 정리합니다.

실행 결과 파일은 Git에서 제외된 `test-results/`에 생성됩니다.

- `pair-report.json`: 실행 시간, 대상 파일 해시, 디스플레이, 각 시나리오 결과
- `pair-host.png`: 양방향 동기화 후 호스트 화면
- `pair-client.png`: 양방향 동기화 후 참여 앱 화면
- `pair-host-closed.png`: 호스트 종료를 감지한 참여 앱 화면

## 검증 범위

하나의 Linux 클라우드 머신에서 OS 클립보드를 분리한 두 실제 앱 프로세스로 검증했습니다. 물리 PC 두 대 사이의 Wi-Fi·방화벽·네트워크 단절, Windows/macOS 네이티브 클립보드, 배포 서명과 설치 프로그램은 이번 실행에 포함되지 않았습니다.
