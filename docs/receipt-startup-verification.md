# 0.4.6 중복 수신·가독성·자동 시작

## 중복 파일

수신 위치의 파일명·크기로 후보를 좁힌 뒤 스트리밍 SHA-256을 비교합니다. 기존 `(1)`, `(2)` 파일과 NFC/NFD 한글 이름도 확인합니다. 폴더의 모든 파일 내용을 해시하지 않으며 저장된 예전 해시를 신뢰하지 않습니다. 검사 전후와 재사용 직전에 파일 ID·크기·수정/변경 시각을 나노초 단위로 확인하고 심볼릭 링크는 재사용하지 않습니다.

새 송신 측의 `offer.reuse`와 수신 측 `accept.have`가 확인된 경우 본문 없이 기존 `finish`/`done` 완료 절차를 거칩니다. 실제 데이터 전송량은 0바이트이며 클립보드는 기존 경로를 가리키도록 갱신합니다. 비교 후 파일이 삭제·변경되면 정상 데이터 전송을 다시 요청합니다. 내용이 다른 파일은 기존 덮어쓰기 방지를 유지합니다.

구버전 송신 측은 기존 절차대로 받고 저장 직전에 비교해 중복 파일 생성을 막습니다. 구버전 수신 측은 새 선택적 필드를 무시하고 정상 전송을 받습니다. 자동 수신은 순서대로 처리해 여러 기기가 같은 파일을 동시에 보낼 때 첫 수신 완료 파일을 다음 수신이 재사용합니다. 일반 수동 수신이 겹친 경우에도 최종 저장 시 비교합니다.

### 실행한 검사 · 2026-10-21 (Asia/Seoul)

- 단위·소켓·미디어 검사: 동일 파일의 실제 데이터 조각 0개, 같은 크기의 다른 내용 보존, 번호가 붙은/NFD 파일, 재시작 후 재사용, 삭제·변경·심볼릭 링크, 비교 후 삭제 시 재수신, 구버전 전송과 동시 자동 수신을 확인했습니다.
- 텍스트를 복사한 직후 같은 파일을 다시 복사해 미디어 검사 사이에 변경이 지나가도, 클립보드 변경 순서로 새 복사를 감지합니다. 상대에게 받은 파일을 다시 전송하는 반복 없이 기존 파일을 재사용하는 회귀 검사를 추가했습니다.
- 실제 500,000,000바이트 한글 프로그램을 암호화 소켓으로 전송하고 SHA-256을 대조했습니다. 다시 보냈을 때 데이터 조각 0개·중복 저장 0개·양쪽 전송량 0바이트를 확인했습니다.
- 같은 클라우드 환경의 이 검사에서는 최초 전송과 해시 대조에 10,533ms, 중복 판정과 재사용에 1,355ms가 걸렸습니다. 첫 값에는 전송 후 독립 해시 대조도 포함됩니다. 메모리 RSS 증가량은 115,290,112바이트였습니다. 사용자 PC와 실제 내부/외부망의 속도를 보장하는 수치는 아닙니다.
- 별도 디스플레이와 OS 클립보드를 가진 패키징 앱 두 개에서도 500MB 전송과 다시 복사 시 기존 파일 재사용을 확인했습니다. 12개 통합 항목 모두 성공했고 한글·이미지·양방향 붙여넣기·재연결도 확인했습니다.
- Linux에서 실제 포인터 창 이동, 보안 저장소와 재실행 후 연결·위치 복원 검사를 통과했습니다.

## 가독성

본문 13px, 보조 글자 최소 12px로 키웠습니다. 배경·버튼·입력 테두리를 구분하고 보조 글자를 더 진하게 표시합니다. 청록색 강조와 투명 아이콘은 유지합니다. 실제 Electron 화면의 주요·보조 글자와 버튼 21곳에서 계산한 최소 대비는 다크 6.97:1, 라이트 5.71:1로 각각 4.5:1 기준을 넘었습니다.

## 부팅 시 시작

설치된 Windows·Mac 앱에서 사용자가 체크할 때만 OS 로그인 항목을 등록하고, 해제하면 제거합니다. 컴퓨터의 사용자 로그인 후 창을 띄우지 않고 트레이·메뉴바에서 시작합니다. 저장된 연결도 복원합니다. 중복 프로세스를 막고 사용자가 다시 실행하면 기존 창을 엽니다. 환경설정의 고정 체크박스는 교체했으며 상단 핀 버튼은 유지합니다.

운영체제의 실제 상태를 설정 화면을 열 때 다시 읽습니다. Windows 시작 앱에서 사용자가 끈 항목을 임의로 다시 켜지 않으며, Mac의 `requires-approval` 상태에는 시스템 설정 안내를 표시합니다. 자동 시작 조회 실패가 앱 실행을 막지 않도록 처리합니다. 개발용 Electron을 실수로 자동 시작에 등록하지 않습니다. 기존 설정 파일에 새 필드가 없어도 테마·단축키·상단 핀을 유지합니다.

Windows에서는 사용자 Run 키의 `ClipSync` 항목과 승인 상태를 확인합니다. Electron의 `openAtLogin`은 기본 AppUserModelID만 조회하므로 사용자 지정 이름에는 `launchItems`를 확인합니다. 경로에 공백·한글이 있어도 정상적으로 조회·실행되도록 따옴표를 처리합니다. 제거 프로그램도 이 앱의 자동 시작 항목을 삭제합니다.

CI는 Windows의 실제 패키지와 `/Applications/ClipSync.app`에 설치한 Intel Mac 패키지에서 체크·실제 OS 등록 조회·재실행·숨김 시작·중복 실행 방지·등록 해제를 검사하도록 구성했습니다. OS별 최종 결과와 배포 다운로드 검증은 완료 후 아래에 기록합니다. 운영체제 재부팅·로그아웃/로그인 자체를 수행하는 검사는 아닙니다. Windows API의 인수 목록은 `--startup` 같은 스위치를 제외하므로, 실제 Run 레지스트리 값도 별도로 읽어 시작 인수가 포함됐는지 검사합니다.
