# 0.4.4 내부 탐색 보완

## 실물 보고서와 확인 범위

같은 공유기를 사용하는 Windows x64와 Apple Silicon Mac에서 0.4.3의 `peers=0`, `beacons=0`, `lastError=null`이 보고됐습니다. 사용자는 두 기기의 키·비밀번호가 같고 Mac 로컬 네트워크/Windows 방화벽에서 앱을 허용했다고 확인했습니다.

0.4.3의 `beacons`는 같은 그룹에 속하고 HMAC를 통과한 신호만 셌습니다. 0개라는 사실만으로 패킷 차단이나 비밀번호 불일치를 구분할 수 없으며, `udpReady`/`tcpReady`는 소켓 준비만 뜻합니다. `routingNodes`에는 이전에 기억한 노드도 포함될 수 있으므로 이 숫자만으로 현재 외부망 접속 성공을 판단하지 않습니다. 공유기의 멀티캐스트 차단은 가능한 원인이며 실물에서 확정한 원인이 아닙니다.

## 변경

- 각 활성 IPv4 어댑터의 IP/넷마스크로 계산한 해당 서브넷의 브로드캐스트 주소에도 발견 신호를 보냅니다. 기존 그룹 멀티캐스트와 공통 ClipSync 발견 그룹을 함께 사용하며 외부 DHT도 유지합니다. 별도 서버·포트 스캔·유료 중계는 추가하지 않았습니다.
- 광고에는 불투명 그룹 식별자·기기 ID·일시 TCP 포트·HMAC만 담습니다. 광고의 HMAC가 유효해야 실제 발신 IP로 접속하고, 이후 양쪽 인증과 기존 AES-GCM 암호화 규약을 통과해야 클립보드를 주고받습니다. 다른 그룹 신호는 진단 수치만 올리고 접속하거나 응답하지 않습니다.
- 보고서에 OS 버전, 광고 송신 수, 전체 수신 패킷 수, 다른 기기의 광고 수, 다른 그룹 광고 수, 인증 거부 수, TCP 접속 시도 수, 브로드캐스트 대상 수를 추가합니다. 주소·기기 이름·키·비밀번호·클립보드는 포함하지 않습니다.
- 기존에 저장한 연결 정보는 유지하며, 직접 발견이 늘어도 기기 중복 연결 정리와 전송 인증은 유지합니다.

## 진단 항목 해석

| 항목 | 의미 |
| --- | --- |
| `announcementsSent` | OS의 UDP 송신 콜백이 성공한 광고 수. 상대 수신을 보장하지 않음 |
| `receivedPackets` | 소켓으로 들어온 전체 패킷. 자기 자신의 멀티캐스트도 포함 가능 |
| `peerAnnouncements` | 자기 ID를 제외하고 광고 형식을 만족한 신호 수. 인증 성공 수는 아님 |
| `otherGroupBeacons` | 그룹 식별자가 다른 광고 수. 주변의 다른 ClipSync 그룹일 수도 있음 |
| `rejectedBeacons` | 같은 그룹 식별자를 사용했지만 HMAC 검증에 실패한 광고 수 |
| `beacons` | 같은 그룹이며 인증된 광고 수 |
| `connectAttempts` | 인증된 광고를 받은 뒤 시작한 TCP 접속 시도 수 |
| `broadcastTargets` | 각 어댑터의 서브넷에서 계산한 브로드캐스트 대상 수 |

두 PC 모두 송신은 증가하지만 `peerAnnouncements=0`이면 아직 다른 PC의 광고가 도달하지 않는 단계입니다. 공유기/AP 격리, 서로 다른 VLAN/게스트망, OS별 네트워크 권한·방화벽을 확인합니다. `otherGroupBeacons`가 증가하면 주변 ClipSync 신호는 도착한 것이므로 연결할 두 기기의 설정을 다시 비교합니다. `beacons`가 증가하지만 연결되지 않으면 TCP 허용·인증 단계를 확인합니다. 접속 시도는 기기 ID를 비교한 한쪽만 시작하므로 양쪽 접속 시도 수가 모두 양수일 필요는 없습니다.

## 검사

- 외부 탐색 노드 없이 멀티캐스트·브로드캐스트를 병행하는 3개 실제 세션에서 인증, 텍스트, 재연결, 잘못된 HMAC 거부를 검사합니다.
- 멀티캐스트를 명시적으로 끄고 DHT 노드도 주지 않는 조건에서 실제 UDP 브로드캐스트와 직접 TCP로 두 세션을 연결합니다. 비밀번호가 다른 세 번째 세션은 연결·클립보드 수신이 없으며, 다른 그룹 신호 수가 증가해야 합니다.
- 서로 다른 X 디스플레이의 패키지 앱으로 텍스트·이미지·한글 파일·500MB 프로그램·보고서의 개인정보 제외/비동기화를 검사합니다.

같은 OS 호스트 내 검사이며 서로 다른 실물 Mac–Windows 연결 성공을 의미하지 않습니다. 두 실물 기기의 재검증 결과가 필요합니다. OS나 공유기가 브로드캐스트까지 차단하는 경우 이 보완만으로 연결을 보장하지 않습니다.
