# ClipSync 0.2.0 이미지·파일 전송 검증

2026년 10월 20일 **21:11 KST**에 최종 Linux 패키지 검증을 완료했습니다. 이 버전은 명시적으로 선택한 PC에 이미지와 파일을 전송하며 파일당 500,000,000바이트를 포함한 크기까지 지원합니다.

## 결과

| 검사 | 결과 |
| --- | --- |
| TypeScript 타입 검사·Vite/Electron 빌드·Linux 패키징 | 통과 |
| 프로토콜·제어·파일·한글 파일명 자동 테스트 | 20개 통과, 실패·건너뜀 0 |
| 실제 소켓 500MB 전송·메모리 검사 | 1개 통과 |
| 패키징된 데스크톱 앱 두 개 | 12개 시나리오 통과, 실패·건너뜀 0 |

데스크톱 테스트 러너는 상위 테스트 1개와 하위 시나리오 12개를 합쳐 13개 통과로 보고합니다. 테스트 전용 파일 선택·저장 경로만 지정했으며 나머지 UI 동작, OS 클립보드, 파일 I/O, 암호화, 소켓 전송은 실제로 수행했습니다.

### 파일·이미지

- 앱 두 개를 서로 다른 Xvfb 디스플레이와 앱 프로필로 실행하고 클립보드 독립성을 확인했습니다.
- 분해된 한글(NFD) 이름의 `.exe` 테스트 바이너리를 UI의 **파일 보내기 → 받기**로 전송했습니다. 수신 파일명이 NFC이고 내용이 원본과 바이트 단위로 같음을 확인했습니다.
- 실제 PNG 클립보드를 **클립보드 이미지 보내기 → 받기 → 이미지 복사**로 전달하고 상대 OS 클립보드의 이미지 형식과 크기를 확인했습니다.
- 정확히 **500,000,000바이트**인 `.exe` 테스트 파일을 앱 두 개 사이에서 전송했습니다. **10.0초** 걸렸고 원본과 수신 파일의 SHA-256이 일치했습니다. 테스트 파일에는 바이너리 헤더, 무작위 데이터와 한글 UTF-8 꼬리 데이터가 포함됩니다. 실행 여부를 검사한 프로그램은 아닙니다.
- 별도의 소켓 스트리밍 검사에서 500MB 전송은 약 10.4초, RSS 증가량은 115,097,600바이트(약 115MB)였습니다. 이는 해당 실행의 측정값이며 모든 플랫폼의 고정 메모리 상한을 의미하지 않습니다.

### 한글·무결성·중계

- macOS 형식의 NFD 파일명과 Windows에서 사용하는 NFC 파일명 정규화, 한글·이모지·확장자 보존
- Windows 예약 장치명·금지 문자·긴 파일명 처리
- UTF-8 한글과 CP949 바이트를 포함한 파일의 무변환 전송
- 정규화 후 충돌하는 파일명에 번호 추가, 기존 파일 내용 유지
- 빈 파일 전송, 500MB 초과 크기의 송신 전 거부
- 전송 중 내용 변조 시 SHA-256 불일치 검출 및 `.part` 삭제
- 수락 전 파일 조각 미전송, 거절·연결 해제 시 부분 파일 삭제
- 클라이언트 → 호스트 및 클라이언트 → 호스트 중계 → 다른 클라이언트 전송
- 기존 텍스트 복사·붙여넣기, 일시정지, 동시 복사, 재연결, 호스트 종료 회귀 검사

## 재현과 결과 파일

README의 클라우드 환경 변수를 설정한 뒤 실행합니다.

```sh
npm run typecheck
npm test
npm run test:large
npm run package
npm run test:pair
```

- `tests/transfers.test.ts`: 파일명·전송·충돌·거절·변조·중계 검사
- `tests/transfer.large.ts`: 실제 500MB 소켓 전송과 메모리 측정
- `tests/desktop.pair.ts`: 실제 앱 두 개의 UI·클립보드·이미지·500MB 전송
- `test-results/pair-report.json`: 최종 실행 결과와 앱 해시
- `test-results/large-transfer.json`: 스트리밍 검사 크기·파일 해시·메모리 측정
- `test-results/pair-files-host.png`, `pair-files-client.png`: 실제 전송 완료 화면

## 범위

실행 검증은 하나의 Linux 머신에서 수행했습니다. macOS·Windows 파일명 규칙과 NFC/NFD 처리를 코드와 테스트로 적용했지만, **macOS·Windows 물리 PC 사이의 실기 검증은 아직 수행하지 않았습니다.** CI에는 두 운영체제의 빌드·자동 테스트를 추가했으며 GitHub에서의 실행 결과는 아직 없습니다. 설치 프로그램, 코드 서명, 각 OS에서 받은 프로그램의 실행 호환성도 별도 항목입니다.
